Two rooms further inside

RoomNavigation.tsx names the three destinations. MuseumScene.tsx owns a temporary room ID and keeps the Main Hall gallery mounted while hidden, so its desktop page and mobile item survive a round trip.

StoryRoom.tsx owns rain, paper petals, seed drawer, telescope, constellation wheel and clockwork comet. StoryRoomAtmosphere.tsx draws the sage glasshouse and plum observatory, with rooms.css handling responsive composition. These optional features never access exhibit/draft storage; leaving resets their UI state. A creation invitation returns to the existing Hall callback and keeps a recovered draft’s stable ID.

The curator stories are explicitly fictional museum lore. They do not interpret visitor input. See the room review and screenshots.

A notebook of its own

MemoryJournal.tsx stays mounted beside the room destination in MuseumScene.tsx. Closing the book or leaving the glasshouse keeps the editor’s exact words in memory. Its native journal dialog reuses PanelDialog.tsx for focus, Escape and restoration. journal.css supplies cream paper, a pressed-fern cover and a mobile page index.

src/model/journal.ts defines journal entries and open drafts independently of exhibits. journalStorage.ts uses almost:journal:entry:<id> and almost:journal:draft. Same-ID retries, raw baselines and read-back checks protect saved pages. First save records the original time and time zone; editing changes only the separate update timestamp. Corruption blocks writes without erasing stored words.

See journal verification and screenshots. Screenshot memories and test records are synthetic, never personal visitor content.

A practice to reuse

Make a visual promise testable before you redesign it. “The reveal never turns on the lasting light” became an explicit PRD criterion, separate App event paths, and a browser test that creates, replays, toggles and reloads. The redesign adds architectural depth, optional room discoveries and an unsaved placement preview while those checks still prove that the light changes only by an explicit action.

The companion test a failed save skips the placement ceremony and never celebrates durable success connects emotional honesty to observable behavior. Another test compares twelve stored records byte for byte across browsing and reload. Reuse that approach: identify the promise that must survive a redesign, give it a visible criterion, and protect it with an executed regression test.

Executed evidence: 57 unit tests and 82 desktop/mobile browser tests passed, alongside typecheck, lint and production build. See the implementation report for limits and the exact checks. This is evidence about the app, not a statement of learner mastery.
